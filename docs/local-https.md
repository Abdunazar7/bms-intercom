# Локальный HTTPS для микрофона (двусторонний звук)

> **Обычно это НЕ нужно настраивать руками.** Интеграция сама поднимает
> локальный HTTPS на отдельном порту (по умолчанию `8443`) с самоподписанным
> сертификатом и сама предлагает кнопку «Открыть по HTTPS». От вас — только
> IP/логин/пароль панели. Один раз примите предупреждение браузера о
> сертификате — и микрофон работает.
>
> Этот документ нужен, только если вы хотите **HTTPS без предупреждений**
> (локальный доверенный сертификат) или собственный обратный прокси/домен.
>
> Примечание: встроенный прокси ходит на HA с `127.0.0.1`, поэтому в логах HA
> клиенты видны как localhost. Если включён бан по IP при неверных логинах —
> учитывайте это; при необходимости используйте внешний адрес (опция
> «Внешний HTTPS-адрес») или собственный прокси с `trusted_proxies`.

Браузер разрешает микрофон (`getUserMedia`) **только в защищённом контексте** —
по `https://` или через `localhost`. По обычному `http://IP` микрофон молча не
работает. Чтобы говорить через домофон, интерфейс Home Assistant нужно открывать
по HTTPS.

Самый удобный способ для локальной сети — **отдельный HTTPS-порт через обратный
прокси**: Home Assistant остаётся как есть на `http://…:8123`, а рядом
поднимается, например, `https://…:8443`, через который и работает микрофон.

```
http://homeassistant.local:8123   ← как было
http://10.10.10.10:8123            ← как было
https://10.10.10.10:8443           ← новый, защищённый → микрофон работает
https://homeassistant.local:8443   ← тоже работает
```

> Проверено: прокси корректно проксирует страницу, **WebSocket** и видеопоток —
> интерфейс HA полностью работает через HTTPS-порт.

## Шаг 1. Самоподписанный сертификат (с SAN)

Главное: в сертификат **обязательно** прописать все адреса, по которым заходят
(в `subjectAltName`) — иначе Chrome не даст открыть. Выполните в аддоне
**Terminal & SSH** (или на любой машине с `openssl`):

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /ssl/intercom-privkey.pem -out /ssl/intercom-fullchain.pem \
  -subj "/CN=homeassistant" \
  -addext "subjectAltName=DNS:homeassistant.local,IP:10.10.10.10"
```

Подставьте свои адреса. Несколько — через запятую: `...,IP:10.10.10.10,IP:192.168.1.50`.

## Шаг 2. Разрешить прокси в Home Assistant

В `configuration.yaml` (HA остаётся на http, HTTPS даёт прокси):

```yaml
http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 127.0.0.1
    - 172.16.0.0/12   # подсеть Docker, где живёт прокси-аддон
```

Перезапустите Home Assistant.

## Шаг 3. Обратный прокси (Caddy)

Поставьте аддон **Caddy 2** (или NGINX) из магазина дополнений, либо запустите
Caddy отдельным контейнером. Конфиг — [`examples/Caddyfile`](../examples/Caddyfile):

```caddy
{
	auto_https off
	admin off
}
:8443 {
	tls /ssl/intercom-fullchain.pem /ssl/intercom-privkey.pem
	reverse_proxy 127.0.0.1:8123
}
```

(в standalone-контейнере вместо `127.0.0.1:8123` укажите имя/адрес контейнера HA).

## Шаг 4. Подсказать интеграции HTTPS-адрес

**Настройки → Устройства и службы → BMS Intercom → Настроить** → поле
**«HTTPS-адрес»**: `https://10.10.10.10:8443`.

Теперь, если оператор открыл дашборд по http, поп-ап вызова сам покажет кнопку
**«Открыть по HTTPS»** — переход на защищённую версию, где микрофон работает.

## Шаг 5. Первый вход

Откройте `https://10.10.10.10:8443` и один раз примите предупреждение о
сертификате («Дополнительно → Перейти»). Дальше микрофон в поп-апе работает.

## Без предупреждений (по желанию)

Самоподписанный сертификат каждый раз просит «Перейти». Чтобы убрать
предупреждение — используйте локальный корневой сертификат:

- **mkcert** — создаёт локальный CA; установите его корневой сертификат на
  устройства сотрудников один раз, и замок станет зелёным без предупреждений.
- либо **Caddy** в режиме `tls internal` (свой локальный CA) + доверие к нему на
  устройствах.

Шаги те же, меняется только источник сертификата в шаге 1/3.
